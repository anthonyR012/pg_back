The way to get cerbot to do this for you and avoid the error without changing your config structure is to comment out the offending line. After certbot succeeds, you'll then need to edit the config files manually to uncomment the lines and make sure you choose a new daemon process name for the new HTTPS config. So, in this case you should:

Put a # in front of the line starting with WSGIDaemonProcess.
Run cerbot again and ask it to attempt to reinstall the existing cert for you. It will succeed this time.
Edit the original configuration file and uncomment the WSGIDaemonProcess line.
Edit the new configuration file that certbot created for you and uncomment the line (certbot will have copied the entire original config file for you, including any comments).
You'll need to rename the daemon process in this file since you can't use the same name in two different virtual hosts; I'd recommend just adding an s to the name for secure: name -> names
Restart Apache.
